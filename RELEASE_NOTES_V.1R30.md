# PSCAL V.1R30 Release Notes

Date: 2026-08-13

Base tag: `V.1R29`

Status: Release candidate

## Summary
- `V.1R30` is 671 commits on top of `V.1R29` (2026-05-20). The largest single item is Aether, a statically-typed frontend that did not exist at `V.1R29` — the tag contains no aether files at all — which now ships as `build/bin/aether` and emits the shared PSCAL AST through rea's frontend hook seam.
- pscal-core moves to VM 2.0: a new PSB3 bytecode container with a load-time verifier, a refcounted object header with copy-on-write value representation, growable stacks, slot-addressed globals, effect classes with a `--deny` sandbox and record/replay, first-class tasks and channels, and loadable plugins through a frozen C ABI. Several long-standing miscompiles are fixed along the way, including `case` range labels that never matched, jagged `arr[i][j]` returning the row instead of the element, inherited methods dispatching through the wrong vtable slot, and `readln` aliasing every copy of the string it filled.
- The components were split into standalone repositories: `pscal-core`, `pascal`, `rea`, `clike` and the newly extracted `exsh` each build, install and test on their own. SmallCLUE now ships its own POSIX shell in place of the vendored dash, adds 27 applets including a real `awk` interpreter, and produces a genuinely static Linux binary.
- The iOS/iPadOS app builds and links again in the split tree, Aether runs on device, and a new macOS CI job compiles the app — previously nothing did, which is how three iOS build breaks reached `main` unnoticed. `CURRENT_PROJECT_VERSION` is bumped 29 -> 30; `MARKETING_VERSION` is untouched.
- Validation to date: `ctest` 5/5 suites pass, the example sweeps pass, and the iOS app builds and links for the iOS Simulator (Debug). The TestFlight archive has not been uploaded yet, so this is a release candidate rather than a final release.

## Highlights Since `V.1R29`
- Aether (new language and frontend):
  - Aether is new in this release: a small, statically-typed language with typed records and methods, `@pure`/`@pre`/`@post` contracts, an `fx` effect fence, tuples and first-class TOON/JSON parsing, designed so a language model can write valid programs from a single guide in its prompt. It carries no VM or engine of its own — it parses its own source, runs its own semantic analysis, and emits the shared PSCAL AST (aether -> rea -> pscal-core). Ships with 65 examples, 213 test fixtures, and its own dated language version (currently `2026-08-11-4`, reported by `aether --version`).
  - The AST parser replaced the original source-to-Rea text rewriter and is now the only frontend. It became the default at the P7 cutover with corpus parity of 1819/1851 and no case where the AST path was worse; the ~10k-line `translate.c` rewriter was then deleted, so `AETHER_PARSER` is no longer consulted and `--dump-rewrite` is gone. The `fx` fence and `@pure` checks became real AST walks instead of physical line scans, closing an escape (an effectful call split across two lines compiled with no `fx`), a false positive (`fx` with its brace on the next line) and a purity hole (a `@pure` function containing an `fx` block).
  - Breaking: Text is now 0-based. `s[0]` is the first character, `s[a..b]` is a half-open substring, `copy(s, start, count)` takes a 0-based start, and `pos(needle, s)` returns `-1` when the needle is absent instead of `0`. Migration is not mechanical — hand-managed cursors (`loop i in 1..string_len(s) + 1`, two-pointer seeds at `1`/`n`, `copy(s, i + 1, 1)`) still compile and silently do the wrong thing, and `pos(...) == 0` as an absent-test is now wrong in both directions.
  - Breaking: the `fx` effect fence now covers all host interaction. Filesystem, `getenv`, `paramstr`/`paramcount`, `random`/`randomize`, the external clock, console input, networking (`http*`/`socket*`/`dnslookup`), `sqlite*` and the `task_wait` family previously escaped both FX-001 and the `@pure` check, so a `@pure` function could read the environment or call `random` and still compile. Those now require an `fx { ... }` block; matching is case-insensitive. SDL/graphics and terminal screen-control builtins are deliberately left ungated.
  - Breaking: `ret` now coerces the returned value to the declared return type. An `-> Int` function ending in `ret (a + b + c) / 3;` previously leaked the raw Real, so `println(meanOfThree(12, 30, 30))` printed `24.000000`; `fn half(a: Int) -> Real { ret a; }` now prints `5.000000` where it previously printed `5`. Rea's `return` had the same gap and is fixed with it.
  - Breaking: the parser rejects malformed input instead of tolerating it. An unclosed block, argument list, index expression, parenthesized expression, if-expression branch, tuple pattern, parameter list or type body emits `[SYN-001] expected '<closer>' ... (opened at line N)`; an unrecognized statement mid-block is a SYN-001 instead of silently truncating the block; an unknown type name in any annotation position is SCOPE-001 rather than reaching the backend as `TYPE_UNKNOWN`; and fourteen fixed-arity builtins called with the wrong argument count now fail at compile time as BUILT-002. The parser's inference and type-flow tables were also scoped per function; they had been program-global, so one function's locals leaked into every later function.
  - Every diagnostic carries a stable code, a hint and a guide pointer. Aether emits `path:line: [CODE] message` across 25 active codes (SYN-001, FX-001, TYPE-001, SCOPE-001, FIELD-001..003, FLOW-001/002, PAR-001/002, TUP-001, ARR-001..003, MS-001, NAME-001, NARROW-001, PREC-001, BUILT-001/002, TOON-001, IMP-001, ANN-001, METH-001, NEST-001), which double as section headings in the LLM guides. `--diagnostics-json` and `--diagnostics-toon` expose code, hint and location to a repair loop. Getting there required retiring 44 raw uncoded parser errors, a SYN-001 backstop so a parse failure can never exit 1 with empty stderr, and a collector backstop that backfills codes for uncoded backend messages.
  - Array slicing `xs[a..b]` works in indexing-bracket position, half-open to match `loop i in a..b`, with the element type inferred from the base array. The if-expression form gained chaining (`let g: Text = if a {x} else if b {y} else {z};`). ARR-001 warns when a `Void` function mutates an array parameter via indexed assignment — arrays are value-copied at the call boundary while records are pointer-backed, so the caller can never observe it; sweeping the 682-item corpus found three real hits, including two sort examples whose recorded expected output was the unsorted input.
  - Bitwise and shift operators `<<`, `>>`, `&`, `|` and `^` (also spelled `xor`) were added. Because `&` and `|` double as eager boolean operators, the new PREC-001 warning fires only when the left operand is provably `Int`: `flags & mask != 0` parses as `flags & (mask != 0)` and yields an Int that prints as `1`, so a permission check written that way looks like it passes.
  - Array `+` concatenation works in chains of any length and no longer corrupts self-referencing operands. All three lowerings peeled exactly one operand, so `a + b + c` reached the VM as a runtime type error; a shared collector now peels the whole left spine. `ys = [0] + ys` clobbered the destination before the copy steps read it and is now hoisted into a temp. Array bounds errors gained ARR-003 with a source line and the valid range.
  - Tuple returns are reentrant. `ret (a, b)` originally lowered each slot to a shared per-function global, which forced compile-time rejection of direct recursion, indirect recursion and `par` branches calling the same function. Tuple returns now synthesize a hidden record type per signature and return it through the reentrant record-by-value path; TUP-001's call-cycle check and PAR-003 were removed. Also added: `.0`/`.1`/`.2` field-index access on a bound tuple, and tuple items that are arrays such as `(Int, Int[])`.
  - Records gained constant field defaults (`type Counter { value: Int = 7; }`, applied for `new T()` and for the unset fields of `new T { ... }`, with FIELD-003 rejecting a non-constant default), record literals as general expressions, and working methods across `use "..."` imports — previously any method call on an imported type died at runtime with `Global '<class>_vtable' not found`.
  - `File` and `MStream` became declarable types. The VM's Pascal-style file builtins always worked but Aether had no type name that satisfied their file-variable check, so `assign(f, path)` failed at runtime with no valid spelling available; `File` now maps to `TYPE_FILE`. `MStream` lowers to `TYPE_MEMORYSTREAM`, making `httprequest` usable from typed Aether, and the new MS-001 diagnostics catch a stream-returning builtin bound to a non-`MStream` type at compile time instead of crashing the VM.
  - Concurrency correctness: a `par` branch whose target was defined below the enclosing function was skipped silently (no diagnostic, no output, exit 0) because `spawn` baked in the forward-declaration stub's address — forward targets now resolve by name at spawn time, and the ORDER-001 rule was retired from the guides. Each thread derives its own random seed, where previously every `par` branch drew an identical sequence. Handing the same pointer-backed record to more than one `par` branch, which aborted the VM with a heap double-free, is now PAR-001 at compile time.
  - Three LLM-facing guides (full 2313-line, medium 1391-line, small-context 943-line) are maintained against the compiler and versioned on the same `YYYY-MM-DD-N` scheme, with a guide changelog recording each revision and the compiler commit it was verified against. `docs/aether_guided_benchmark.md` and `docs/aether_specialization_findings.md` record the measured results that drive language changes; the stated policy is that a construct capable models consistently reach for and cannot find is treated as a language bug.
  - Other fixes: a SIGBUS/SIGSEGV crash on ordinary recursive functions that divide their argument (`digitSum` recursing on `n/10`); `readln` no longer aliases every copy of the Text it fills; a function may share a type's name; an inferred `let` from `new C()` resolves to the pointer-backed record type; trailing `//` comments on `@pre`/`@post` annotations no longer leak into the contract guard; reserved-word collisions in a field or method name are named by the diagnostic; whole-array-to-scalar contract predicates are rejected as ANN-001 instead of aborting the VM; `continue` inside a range loop no longer produces a bogus SCOPE-001; ARR-002 catches a one-dimensional array indexed twice; NARROW-001 warns on implicit Real -> Int truncation into an explicit `: Int`, including zero-argument `random()`; `aether --version` reports the language version rather than the PBuild build timestamp; digit separators are accepted in numeric literals; and multiple constructs sharing one physical line parse instead of silently dropping a method.
- pscal-core (VM, bytecode compiler, semantic analysis, type system, builtins):
  - `case` statements with range labels never matched: the compiler emitted the case value and the range bound in the wrong stack order, so `case i of 1..3:` silently skipped `i=2` and any program relying on case ranges took the else/default branch.
  - Chained indexing into a jagged array returned the row, not the element. `arr[i][j]` dropped the second subscript, and an assignment with `j != 0` clobbered the whole row. Flat multidimensional arrays declared `array[1..3,1..3]` were never affected; a separate fix covers `f[1][2]` on a genuinely flat array, where the first bracket compiled as a complete scalar offset.
  - Functions declared to return an integer could return a Real: `returnFromCall` now mirrors call-time parameter coercion in both directions. Pascal was unaffected because assignment to the result variable already coerced.
  - Array-literal initializers no longer produce void, truncated or wrongly typed elements. A literal with any non-constant element stored `TYPE_VOID` with no error; a negative integer literal fell through to void or a stray Real; folded string literals were permanently capped at their initial length; fixed-size and `const` array initializers failed with `Invalid array dimension size (0..-1)`; and an array literal of records could fail with a spurious `Cannot assign ARRAY to integer` when its hidden scratch slot was recycled.
  - `spawn` of a forward-declared routine ran an empty stub — the branch did nothing, printed nothing and exited 0. Forward targets now resolve by name at spawn time; already-compiled targets keep the direct address and produce byte-identical bytecode.
  - Worker threads drew identical random sequences from the same constant seed, so a parallel Monte Carlo or shuffle reported a confidently wrong aggregate. Threads now derive independent streams from a shared base mixed with a per-thread index; a run with no `Randomize()` is still bit-for-bit reproducible.
  - Shallow recursion could crash with SIGBUS or SIGSEGV: `setTypeValue` did not clear `Value.bits` when retyping into a box-owning type, so a leftover NaN-boxed payload was later misread as a live box pointer and released.
  - Breaking: stale cached bytecode could dispatch to the wrong builtin, because builtin ids are dispatch-table indices baked into compiled bytecode and adding `pow()` mid-table shifted every later id. `pow` moved to the end of the table restoring every legacy id, a pinned sentinel list fails fast at startup if the table is reordered, and `CALL_BUILTIN_PROC` trusts a baked id only when it agrees with the name compiled alongside it.
  - Breaking: VM 2.0 introduces the PSB3 bytecode container — explicit little-endian header/directory/sections, varint run-length line tables, u32 call and i32 jump operands (a chunk's code is no longer capped at 64KB of jump/call targets), and all reads through a bounds-checked cursor — plus a load-time verifier that validates operands, jump targets and per-procedure stack depth. Old PSB2 caches simply recompile, but a hand-distributed `.bc` must be rebuilt.
  - Breaking: VM 2.0 re-represents values on an atomically refcounted `ObjHeader` with a tagged-word encoding and copy-on-write, so reads alias and retain instead of deep-cloning. Two user-visible consequences in CLike: `int` now truncates on overflow exactly like Pascal's `Integer` instead of silently widening past 32 bits, and `float` has genuine 32-bit IEEE-754 storage, so `(double)(float)3.14 != 3.14`.
  - VM 2.0 also brings growable operand and call stacks, slot-addressed globals with per-chunk inline caches, and a capacity field on `SetLength` that makes the `arr = arr + [x]` idiom amortized O(1). The append change was measured against a 40,000-element text append loop that took 71.6s before the fix and a 63,545-stanza parse that took 247s.
  - Effect classes, a `--deny` sandbox and effect record/replay: every builtin is classified with an effect mask (pure, io, net, proc, clock, random) from a single authoritative predicate. `--deny io,net,proc,clock,random` (or `PSCAL_VM_DENY`) raises a clean runtime error before a denied builtin runs, and `--fx-record`/`--fx-replay` journal effectful builtins' results and VAR-param writebacks. The flags are wired into all five frontends.
  - Tasks and channels are first-class types: `TYPE_TASK` adds `TaskSpawn`/`TaskAwait`/`TaskDone`/`TaskCancel` over the existing thread pool, and `TYPE_CHANNEL` adds `ChannelCreate`/`Send`/`Receive`/`TrySend`/`TryReceive`/`Close`/`IsClosed` as a refcounted shared ring buffer with cancellation-aware blocking. The HTTP async builtins return tasks, and CLike gained `task` and `channel` keywords.
  - Loadable plugins through a frozen C ABI: a versioned `PscalExtHostApi` vtable and `pscal_ext_register` entry point let a shared library register builtins without seeing raw `Value` internals. Plugins load via `--ext <path>` or `PSCAL_EXT_DIR` and are vetted by a fork-based probe, can be disabled with `--deny ext` or at build time, and the `sqlite` category ships as a proof plugin producing byte-identical output to the static build.
  - Concurrency correctness across the VM: `SetLength`'s resize is serialized against concurrent reads, three narrower dynamic-array races and a fresh-publish/jagged-index overflow were closed, five missing-atomics races found by ThreadSanitizer were fixed, thread-pool worker slots are returned instead of leaking a pthread per spawn, a task that aborted with a runtime error is no longer recorded as a successful nil result, and comparing an ordinary value against `nil` no longer throws `Operands not comparable`.
  - A `unicode` text type runs through the lexers, type system, VM and builtin surface for Pascal, Rea and CLike, with a full compatibility audit of the builtin library. Follow-ons: `chr()` covers the whole Unicode range instead of stopping at 255, `ord("a")` no longer errors on a single-byte string, `byte("a")` returns 97 instead of 0, multi-byte literals can be assigned into a `string[N]`, and `parse_int`/`parse_float`/`parse_bool`/`split`/`trim` accept the wide char that `s[i]` produces.
  - Breaking: a double-quoted single character is a one-character string, not a Char. Shared len-1 literal handling demoted Rea's and Aether's `"x"` to Char, which broke calls (SDL among them) that want a string. Pascal's and CLike's single-quoted `'x'` is unchanged, so `ord('A') = 65` still holds.
  - Breaking: argument passing coerces numeric types consistently and narrowing is now an error. A Real passed to an Int parameter is truncated the way assignment does, and the strict integer-family check that rejected the common `f(..., length(x))` pattern is gone. Coercion is widening-only: passing a wider int into a narrower parameter keeps the type-mismatch error. Pascal and CLike have INT32 parameters where this changes previously accepted code.
  - New builtins: `parse_int`, `parse_float`, `parse_bool`, `split`, `itoa` (alias of `IntToStr`), `pow(base, exp)` as a C-style alias of `power`, and `clamp(x, lo, hi)`, which returns Int for integer arguments and Real if any argument is real.
  - Runtime diagnostics carry a source line and a code: an out-of-range array index is raised inside the VM as `[ARR-003]` with a location and a hint instead of a bare message with no file, line or code. `has_builtin` was inverted for core builtins — it reported a working capability as missing — and Unicode string constants print in bytecode disassembly instead of appearing blank.
  - Other fixes: `BlockRead`/`BlockWrite` were missing from the builtin VAR-parameter list, so every use on a `file of X` failed; a Rea method calling another method on `self` emitted the receiver twice; a use-after-free in the interface `is` safe cast; the closure-escape flag was not round-tripped through the bytecode cache; `freeAST`'s unbounded freed-address list made teardown quadratic and type-registry ASTs were never freed; an embedding cycle in record or class definitions died as a bare stack-overflow segfault and is now a clear error; and `exec()` of an interactive job-control child could leave the parent's terminal permanently stuck.
- Pascal, Rea and CLike frontends:
  - Breaking: `result` is no longer a return-value alias in CLike and Rea. The shared compiler unconditionally added Pascal's Delphi-style `Result` local to every value-returning function, so a user global named `result` was silently shadowed and a spawned thread's write to it was invisible to main after join. The alias is now registered only for Pascal and Aether; CLike or Rea code that relied on it must use an explicit `return`.
  - Breaking: CLike treats compile errors as fatal. It previously ignored the shared compiler's return value — exiting 0, caching the broken chunk and executing it — and now prints a summary, skips the cache and exits 1, with the REPL declining to run a snippet that failed to compile. Separately, `&x` passed where a VAR parameter is expected (`getdate(&yr,&mo,&dy,&dow)`, `gettime`, `getmousestate`) emitted an L-value error per argument and segfaulted; `compileLValue` now handles address-of nodes.
  - CLike compiles through the shared bytecode compiler: the frontend lowers into the shared PSCAL AST and drives the common `annotateTypes` plus `compileASTToBytecode` pipeline, deleting its 1,979-line bespoke codegen. C `for` loops, `do`/`while`, `switch`, division by operand type, struct declarations and `scanf` are handled as desugarings, and `&&`/`||` now short-circuit correctly.
  - Inherited methods dispatched through the wrong vtable slot in Rea: each class numbered its methods from zero while a subclass filled unoverridden slots from its parent, so with `Cube extends Square extends Shape` an inherited `area()` re-entered `volume()` and blew the call stack, and at two levels a `perimeter()` built on an inherited `sides()` quietly returned the area. A new pass assigns slots once the hierarchy is known.
  - A free function sharing a class's name hijacked its constructor. Because Rea and Aether identifiers are case-insensitive and a class publishes its constructor under its bare name, `new Widget()` called a free function named `widget` with the fresh object as its first argument — aborting on an arity mismatch, or silently running that function during construction on a match — and at definition time overwrote the constructor's bytecode address.
  - Rea module and import semantics: an exported class lost its field and method information after the module's own analysis, so an importer's `p.x` reported `identifier x not in scope`; a global `var` typed with an imported class failed with `Cannot assign POINTER to UNKNOWN_VAR_TYPE`; a module could not call its own export through its qualified name; a parameter typed with an imported class kept an unresolved snapshot; a dependency file's own top-level `main()` overwrote the importing program's entry point; forward references reported a bogus `expects 0 arguments`; and any method call on a class carried across a `use` import died with a missing vtable global.
  - Breaking: Rea language additions — digit separators in integer, hex and floating-point literals; `new T { field: value, ... }` as an expression, including inline inside array literals, with partial sets and a trailing comma tolerated; and constant field defaults in class bodies, applied at `new` on top of the type zero and overridden by a constructor or record literal. Non-constant defaults (calls, field references, populated array literals) are now rejected at parse time; they previously compiled the computed initializer into every `new`.
  - Pascal parser and runtime catch-up: case branches whose labels are signed or expression constants (`-1:`, `Ord('q'), Ord('Q'):`) are recognized; a procedure pointer in an array element can be called as a statement (`Pending[I]()`); label declarations after `var` blocks parse; inline for-variable types propagate; interface `is`/`as`, zero-argument interface dispatch and interface array results work; record embedding, the `spawn` syntax, anonymous closure captures and ordinal array bounds are supported. Two use-after-frees in adjacent string-literal concatenation made compilation nondeterministic — roughly 5% of runs produced wrong literal types and corrupt codegen — and are fixed.
  - Other Rea fixes: a trailing `//` comment after an identifier, `)` or `]` was lexed as integer division when the comment text contained expression-like punctuation; the `continue` rewrite left the spliced post-statement orphaned from the scope chain, producing a spurious `identifier not in scope`; a receiver whose own name matched one of its type's field names had its type silently overwritten; the "legacy method call is no longer supported" check rejected the common `db_open()` convention; and a self-referential class field (`class M { M other; }`) segfaulted on `new M()`.
- exsh and SmallCLUE:
  - Breaking: `src/shell` was extracted into `github.com/emkey1/exsh` and is pinned at `components/exsh`; the umbrella compiles the shell from the submodule and no longer carries an in-tree copy. Docs, examples and the exsh test corpus moved with it, leaving `Tests/run_exsh_tests.sh` as a thin shim that runs the submodule corpus against the umbrella binary. exsh also builds standalone against pscal-core via FetchContent.
  - Breaking: SmallCLUE ships its own POSIX shell and dash is gone. The new BusyBox-ash-class `sh`/`ash` applet covers full POSIX word expansion, pipelines with `pipefail`, subshells, brace groups, loops with `break`/`continue N`, `case`, functions with local scope, heredocs, traps, `set -e/-u/-x`, C-style arithmetic, and a raw-mode line editor with history and tab completion, and honours login-shell semantics. dash and linenoise were removed from `fetch_dependencies.sh` and both setup scripts, so `/bin/sh` in the guest rootfs is now SmallCLUE's shell. Shell-restriction errors now exit 2 instead of 1, matching dash.
  - 27 new applets, including `awk` as a genuine lexer/parser/tree-walking interpreter (~3000 lines) covering BEGIN/END, regex and range patterns, user-defined functions with array-by-reference, associative arrays with SUBSEP, every `getline` form, `print`/`printf` redirection and the standard builtin set. Also new: `printf`, `expr`, `timeout`, `tar` (ustar with transparent gzip), `gzip`/`gunzip`/`zcat`, `diff`, `patch`, `dd`, `od`, `cmp`, `base64`, `chown`/`chgrp`, `install`, `nohup`, `chroot`, `readlink`/`realpath`, `md5sum`/`sha1sum`/`sha256sum`, `seq`, `nl`, `tac`, `rev`, `fold`, `paste`, `split`, `fmt` and `comm`, plus a real `/proc`-based `top` on Linux. The documented applet list grew from 81 to 108 entries.
  - A flag-completeness pass across roughly 30 existing applets: `sort -n/-k/-u/-t/-c/-C/-m` with genuinely stable sorting, `cut` field/char ranges and `-s`, real `tr -d/-s/-c` with ranges and POSIX classes, `cat -n/-b/-E/-T/-A/-s`, `uniq -d/-u/-i/-f/-s/-w`, `ls -R/-S/-X/-r/-i/-v`, `grep` real regex plus `-r/-R/-c/-o/-w/-x`, `find` with `-type/-iname/-maxdepth/-mindepth/-delete/-exec/-mtime/-newer/-size/-print0` and full boolean logic, `sed -e/-f` and address ranges, `cp -r/-R/-a/-p`, `xargs` external-binary execution with `-0/-I/-n/-t`, `test`/`[` compound `-a`/`-o`, `stat -c/--format`, `touch -c/-a/-m/-r/-t/-d`, `chmod -R`, `date -d/-s`, `echo -e/-E`, signed `-n` forms for `head`/`tail`, `umount -l/-f`, `wc -m/-L`, `rm --preserve-root` and `-R`, and `git` submodule status/update, `clone --depth`, `log --graph/-p` and credentialed HTTPS/SSH transports.
  - Networking applets gained real protocol support: `ping` speaks IPv6 (and a genuine reply-matching bug was fixed while testing it); `telnet` performs real IAC/DO/WILL/WONT negotiation; `nslookup`/`host` became a real DNS client with custom server override, MX/TXT/NS/SRV queries, reverse/PTR auto-detection and DNS-over-TCP fallback; `ipaddr` does address add/del, link set up/down, route add/del and addr flush over real netlink on Linux; and `curl`/`wget` accept `-X`/`-H`/`-d`, `-u` basic auth and `-k`/`--no-check-certificate`.
  - `rsync`, via the vendored openrsync fork, gained real payload compression under `-z/--compress`, `--progress`, daemon-push, `--compare-dest`/`--copy-dest`/`--link-dest`, and `-c/--checksum` with its poll timeout bounded by default; `rsync -u` was also fixed.
  - The Linux SmallCLUE build is now genuinely static and says so at build time. Nothing in `CMakeLists.txt` ever passed `-static`, so a plain configure-and-build silently produced a dynamically linked binary. `-static` is now forced on UNIX-not-Apple with a POST_BUILD `readelf` check that fails the build loudly otherwise, which exposed and fixed three latent gaps (CURL and libssh2 defaulting to `.so`, and libcrypto.a's zlib/zstd BIO objects). Where Debian/Ubuntu's system libcurl cannot be statically linked because of its gssapi dependency, the build vendors and builds its own static libcurl rather than silently disabling curl, and resolves the libssh2/OpenSSH chacha20-poly1305 duplicate-symbol collision with `objcopy`.
  - SmallCLUE dependencies moved to real submodules and the build no longer needs root: libgit2, openrsync, nextvi and dvtm were fetched via bare clones (or, for openrsync, not fetched at all in a standalone checkout) and in two cases patched with `sed`; all four are now pinned submodules. `setup_posix_env.sh` was split so dependency fetching, stub generation, OpenSSH/dvtm/libgit2 builds and SmallCLUE compilation happen in a new `build_smallclue.sh` with no root check, leaving only rootfs/chroot assembly behind `sudo`. SmallCLUE also got its first CI job, building on macOS and Linux.
  - exsh exposes the VM 2.0 sandbox and plugin flags: its argv loop recognises `--deny`, `--fx-record`, `--fx-replay` and `--ext`. Plugin loading can be shut off at runtime with `--deny ext`/`PSCAL_VM_DENY=ext` (composing with the other effect classes and included in `all`) or compiled out with `-DPSCAL_ENABLE_EXT_PLUGINS=OFF`. `Docs/pscal_ext_plugin_guide.md` documents writing, building, loading and gating a plugin.
  - Bootable PSCAL rootfs tooling: `tools/` gained a pipeline that cross-builds all five frontends plus SmallCLUE for aarch64 glibc in a Debian container and assembles a from-scratch merged-usr rootfs, using SmallCLUE's `init` applet as PID 1 and exsh as the interactive login shell. Boot chain, frontend execution, fork/exec/pipes and background job control were verified end to end under ish-AOK; follow-ups added a PS1 prompt, `/etc/shadow` with nobody/nogroup, sshd under runit in `/etc/service`, and a real `/bin/login`.
  - Other fixes: exsh no longer loses the terminal's foreground process group on exit (`runInteractive()` seized the tty when `opt_monitor` was set but never handed it back on the EOF or exit-builtin paths); SmallCLUE's `init` reaps any exited child while `/etc/rc` runs, so reparented orphans no longer accumulate as zombies; `ls -l` and `stat` report real device-node types instead of a bare `-`, and `mount` no longer passes the literal string `auto` to `mount(2)`; `du` reports actual disk usage and only directories by default and gained `-c/-x/--max-depth`, and `df` enumerates all mounts with no path; `mv` routes through cp's recursive copy on EXDEV; `hostname` actually sets the hostname via `sethostname(2)`; `time` can time external binaries on non-iOS builds; and `ps` gained `-p/-u/-f` and a real STAT column.
- Build system, CI and test harness:
  - CI had been red on `main`: the plan step's frontends and target_mapping tables never listed `aether`, so `ctest` ran `Tests/run_aether_tests.sh` against a binary that was never built. Adding aether to both tables fixed it.
  - A new macOS CI job compiles the iOS app with `xcodebuild`, path-gated and with the bundled libcurl tarball pinned by SHA-256. Every job previously ran on Ubuntu and none invoked `xcodebuild`, so Swift changes and iOS-only C paths reached `main` entirely unbuilt.
  - The example sweep no longer aborts wholesale when a frontend emits a non-UTF-8 byte, and a stale expected-compile-failure entry was removed because escaping capturing closures are a supported feature now.
  - All 12 submodules now declare a tracking branch, so `git submodule update --remote` advances them to their branch tips.
  - `run_all_suites.py` gained four opt-in suites: `--include-vm-verify-corpus` (the verifier's malformed-`.bc` corpus), `--include-vm-fx-policy` (the `--deny`/`--fx-record`/`--fx-replay` regressions), `--include-vm-thread-stress` (task/channel concurrency), and `--include-vm-ext-plugin` (the dlopen plugin ABI, which skips cleanly when the sqlite plugin was not built). `Tests/vm_diff_harness.py` runs the Pascal/CLike/Rea/Aether corpora through two VM builds and byte-compares stdout, stderr and exit codes, re-running divergent units so nondeterministic fixtures classify as NONDET rather than failing, and `Tests/vm_bench` adds six self-timed Pascal benchmarks with checked results and a git-SHA-stamped `history.jsonl`.
  - The components were split into standalone repositories with their own builds: pscal-core, pascal, rea and clike each gained a standalone CMake build (frontends consume the core via FetchContent), an install target, ctest wiring, and their own docs and test corpus. Two new build options: `PSCAL_SDL` for the SDL graphics/audio and 3D backend (default OFF) and `PSCAL_CURL` for the real libcurl networking builtins, which previously had no way to be enabled at all.
  - Breaking: `cmake --install` works from outside the build tree. `CMAKE_BINARY_DIR` is a configure-time variable and was not defined while `cmake_install.cmake` ran, so the bracket-quoted `install(CODE)` blocks degraded to `cmake --build ""`, which falls back to the current working directory — the install only ever worked when run from the build tree. The install step now sources example programs from `components/{pascal,clike,rea,aether,exsh}/examples/` rather than the stale root `Examples/` tree, and the `tiny.pbc` precompile is best-effort.
  - Breaking: the top-level `Tools/` directory was consolidated into `tools/`. The repository carried both as case variants, which is a silent hazard on the case-insensitive macOS filesystem and a real split on the Linux build hosts, where `git add` could no-op across the two; 55 files moved and every reference was repointed.
  - `pscald`, `pscalasm` and `tools/tiny` were ported to VM 2.0 after Phase 4 collapsed `Value` to a 16-byte `{ VarType; uint64_t }` and Phases 2a/2b retired the global/inline-cache opcodes. `tools/tiny` now parses `opcodes.def`'s explicit `OP()` entries instead of a plain enum out of the pre-split `bytecode.h`, and `pscald --emit-asm` disassembles unlinked bytecode so a rebuilt `.pbc` can be relinked.
- iOS/iPadOS app and project:
  - The iOS app builds and links again. The `components/` split left the target unbuildable: curl's `check_symbol_exists()` reported `pipe2` as present when cross-compiling, but the iOS SDK never declares it, so `lib/socketpair.c` killed the configure before anything linked. `HAVE_PIPE2` is now forced off for `PSCAL_REAL_IOS` builds only, and with matching pscal-core/aether/smallclue pins the app builds and links for the first time in the split tree.
  - Two more iOS build breaks that had reached `main` unnoticed: SmallCLUE's `system()` and `clock_settime()` calls are now guarded behind `PSCAL_TARGET_IOS` (neither is usable from a sandboxed app — `awk`'s `system()` routes through `popen()`/`pclose()`, and `date -s` reports plainly that it cannot set the clock), and `sdl.c` applied the PSCAL `VALUE_TYPE` macro to an `SDL_Event` in the iOS `WaitKeyEvent` branch and now compares `SDL_Event.type` directly.
  - Aether runs on device: `aether_main` is registered in the tool runner's descriptor table and `pscal_aether_static` is linked into the iOS tool runner, so `aether` is available in the app's terminal alongside `pascal`, `clike` and `rea`. A new `ios/Tools/bundle_examples.sh` aggregates `components/<lang>/Examples` into the bundle's `Examples/` directory, restoring what `RuntimeAssetInstaller` seeds into `~/Examples` — after the repo split the shipped app contained only a few stragglers.
  - ncurses TUIs render correctly: hterm mapped CSI b (REP, "Repeat Preceding Graphic Character") to `hterm.VT.ignore` and silently dropped it, and ncurses uses REP to fill character runs in the C/non-UTF-8 locale, so every run collapsed leftward and garbled htop meters and headers. hterm now tracks the last printed character and implements CSI b with xterm/ECMA-48 semantics, clamped to the screen area.
  - Terminal-mode programs no longer crawl. CRT builtins issued a `write()` syscall per escape sequence; stdout is now fully buffered (64 KB, `_IOFBF`) on entering terminal mode, the unconditional flush in `vmBuiltinGotoxy` is gone, the Write flush is gated so file streams still flush but stdout does not, and a single `fflush(stdout)` at the head of `ReadKey`/`ReadLn`/`KeyPressed` sends the completed frame exactly once before blocking — roughly 3000 syscalls per frame down to a handful of multi-KB writes.
  - Ctrl-C interrupts the running program instead of killing the shell. SIGINT is blocked process-wide and owned centrally: a per-foreground-tool `sigwait` catcher converts Ctrl-C into the VM abort flag for frontends and a SIGUSR1 longjmp poke for applets, frontends no longer install competing handlers, and ISIG is kept on a plain host TTY. A companion vproc fix makes blocked in-proc pipe reads/writes and `poll(-1)` waits observe pending signals as EINTR.
  - Accessibility: the terminal's fixed accessory bar is now a `UIInputView` subclass conforming to `UIInputViewAudioFeedback` with `enableInputClicksWhenVisible`, and every accessory button calls `UIDevice.current.playInputClick()` on touch-down, so the Esc/Tab/Ctrl/arrow keys sound like keyboard keys. Copy Report in App Diagnostics and the copy-terminal-colors action in Terminal Settings fire a `UINotificationFeedbackGenerator` success haptic and post a VoiceOver announcement ("Report copied to clipboard", "Copied first tab colors"), with the transient Copied state wrapped in `withAnimation` and an explicit `accessibilityHint` on the Copy Report button. These were previously silent, visual-only state flips.
  - `CURRENT_PROJECT_VERSION` bumped 29 -> 30 in both configurations; `MARKETING_VERSION` untouched. The vproc/tty platform layer moved out of `src/ios` into core (`src/runtime/vproc`), with back-compat headers left at the old `src/ios` paths so the Xcode project and smallclue keep resolving `ios/vproc.h` unchanged.
  - No Swift SSH or networking file was touched in this range; the last such work shipped in `V.1R29`. The settings and diagnostics changes are feedback and accessibility only — no setting was added, removed, or had its default changed.
