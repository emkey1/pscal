# PSCAL V.1R34 Release Notes

Base: `V.1R33`

## New in the iOS app
- `ip`, iproute2's command for the device's network, in Linux's layout and words: `ip a` (`ip address show [dev NAME]`), `ip link`, `ip route` and `ip route get ADDRESS`, with `-4`, `-6`, `-0`, `-br`, `-o`, `-j` and `-p`. The loopback interface is `lo`, as on Linux; the others keep iOS's names (`en0`, `pdp_ip0`, `utun0`).

## New in exsh
- exsh has a version of its own: this release is exsh 2.0.0. It is `MAJOR.MINOR.PATCH`, bumped once per release that changes exsh (MAJOR when a script that worked can break, MINOR for new features or changed behaviour, PATCH for fixes only), with each release's entry in exsh's `CHANGELOG.md`. `exsh --version` and `exsh -v` print `exsh 2.0.0` and then the build's details, and a script reads it from `$EXSH_VERSION`, or in parts from `EXSH_VERSINFO`, laid out as `BASH_VERSINFO` is. `BASH_VERSION` stays `5.2.0(1)-exsh`. `VERSION` held `2026-09-19-1`, a date that was never bumped.

## Fixed in exsh
- The prompt takes characters beyond ASCII, typed or pasted. Any byte past ASCII, such as `é`, `ü`, `⚡`, a CJK character or an emoji, was dropped with a bell, so `echo é⚡x` ran as `echo x`. A character now goes in whole, combining marks included. The cursor keys, Backspace, Delete and Ctrl-T move by the character, a wide one takes two columns as on the terminal, and history, reverse search, completion and wrapped lines all hold such characters. Bytes that make no character go in as they are, as in bash. Option-b, -f, -d, -t and -. still run their shortcuts (word back, word forward, delete word, swap words, last argument), as Esc-b and so on do, so those five symbols can't be typed at the prompt.
- `history` takes bash's options. `-c` clears the list, `-d N` deletes an entry (a negative `N` counts from the end, and `START-END` deletes a range), `history N` lists the last `N`, `-s` adds its words as one entry, `-p` prints its words with history expansion done and stores nothing, and `-a`, `-n`, `-r` and `-w` append to, read from and write the history file, `$HISTFILE` when none is named, keeping bash's count of what `-a` and `-n` still have to do. At a prompt, `-s` and `-p` drop their own line, as bash's do. Entries are numbered as bash numbers them. `history` ignored all of its arguments, so `history -c` cleared nothing.
- A `)` that nothing opened is a syntax error, status 2, as in bash: `eval 'echo )'` printed `)` with status 0, and `echo x)y` printed `x)y`. A `)` that closes an unquoted `(` word of the same command, as in `find . ( -name a )`, is still a word.
- `[[ a < b ]]` and `[[ a > b ]]` compare as the locale collates, as in bash 5: under `en_US.UTF-8`, `[[ a < B ]]` is true. They compared bytes. `test` and `[` still compare bytes, as bash's do.
- A shell started as a command starts with an empty history list, as a new bash does. In the app it had a copy of the prompt's.
- The two host tests that disagreed with bash 5.3 on macOS pass against it and against bash on Linux. With no locale variable set, bash sorts a glob and compares in `[[ ]]` in C order on Linux and as macOS's own `/bin/bash`, as exsh does; a bash built with GNU libintl on macOS, such as Homebrew's, takes the Mac's language setting instead, so the tests no longer compare that case.

## Fixed in the iOS app
- A shell that `nohup` starts, or one started after `trap '' HUP`, has HUP ignored on entry, as on Linux: `nohup sh -c 'trap "echo got" HUP; kill -HUP $$; echo after'` prints only `after`, and `trap -p HUP` there lists `trap -- '' SIGHUP`. The trap caught the signal. The same holds for any signal ignored in the task a shell starts in.
- `ping` gets replies. Every request went out with its checksum's two bytes swapped, so every host, a LAN host, the router and the app's own loopback alike, dropped it as corrupt. Each packet then ended in `Request timeout for icmp_seq N (Resource temporarily unavailable)`, with 100% loss.
- `df` shows the app's own filesystems: the root as `rootfs` on `/`, with the size and free space of the app's storage, and anything mounted in the app. It read the device's mount table, so it printed `No such file or directory` for each of the device's own volumes and listed the rest on `/` under Apple's volume names. `df`, `df -h`, `df /` and `df .` agree.
- `/proc/mounts`, `/proc/mountinfo`, `mount` and `stat -f` read the same table: the root is an `ext4` filesystem called `rootfs`, `/proc` is a `proc` filesystem with no blocks, a folder mounted from inside the app's storage is on `rootfs`, and one from outside it is `external` (`fuse`). No host path or volume name shows. `stat -f /` said `UNKNOWN (0x1a)`, `stat -f /proc` said `No such file or directory`, and a bare `mount` printed `/proc/mounts` lines; it prints util-linux's `SRC on DIR type TYPE (OPTS)` as on Linux.
- `mount -p` writes `/etc/fstab` in the app's own terms: a folder in the app's storage by its path there, and one from outside it, such as a folder from the picker, as `UUID=...`, a label the app keeps for that folder. It wrote the device's path for both. A line with a device path from an earlier build still mounts at launch.
- `fstatfs` and `fstatvfs` on a descriptor name its filesystem from the same mount table as `statfs`; a terminal is on `devpts` and a pipe on `pipefs`. They gave the device's volume and mount point.
- `/proc/net/dev`, `/proc/net/route`, `/proc/net/if_inet6` and `/proc/net/ipv6_route` come from the same reading as `ip`, and agree with it. `route` wrote its addresses byte-swapped, listed loopback and had no default route; `if_inet6` gave `::1` the wrong scope and kept iOS's scope bits inside link-local addresses; `ipv6_route` was made up; and `dev` counted no drops or multicast.
- An ended ssh session is gone from `ps`, `top`, `lps` and `/proc`. Each ssh tab or window is a child of pid 1, and pid 1 never reaped one, so every session that had ended, a failed connection included, stayed as a zombie of pid 1 until the app restarted, and pid 1 showed `sigchld` for good. Pid 1 now reaps its own children as they end, as init does on Linux.
- No process is left running after a tab or window closes. The `exsh` with no terminal and its own session that `ps` and `top` showed was no shell: it was the app's own process id, given a row when the first tab's shell started. Its "CPU time" was how long the app had been open, a tenth of it shown as system time, which is also where `top`'s 25% usr with nothing running came from. Opening a second tab also renamed the first tab's shell from `shell` to `exsh`. A task whose CPU time can't be measured now shows 0, not its time alive.
- `ipaddr` reads the same data as `ip`, so its loopback is `lo`, as in `ip`, where it said `lo0`, and a link-local address has no `%en0` after it.
- `ssh-keygen` no longer ends the app or hangs on its second run. Each run after the first freed the last run's `-N`, `-P`, `-I` and `-n` values, which were never its to free, so the second `ssh-keygen` since launch could end the app, say `Too many arguments`, or leave the memory damaged for whatever ran next. Two at once also shared their options.
- `ssh-keygen` takes the end of input at a passphrase question as an empty answer, as on Linux. Once its input had ended it waited for good, so `ssh-keygen -t ed25519 -f key < /dev/null` with no terminal hung.
- `ssh-keygen -y` writes the public key to its own output: `ssh-keygen -y -f key | cut -d' ' -f1` and `k=$(ssh-keygen -y -f key)` got only the comment, and the key itself went to the app's output, past the pipe. Only `> file` worked.
- `ssh-keygen` reads its own standard input: `echo y | ssh-keygen -f key ...` answers `Overwrite (y/n)?`, and `ssh-keygen -l -f -` reads a pipe or redirection. Both read the app's own input instead, so an answer never arrived.
- A program writing to a pipe or FIFO whose reader has gone takes SIGPIPE, as on Linux, and by default ends with status 141: `clike x | head -1` and `pascal x | head -1` end, and `yes | head -1` gives 141 in `PIPESTATUS[0]`. Such a program used to run on with its writes failing (`EPIPE`), so the command line never ended until `kill`. The kernel layer now raises the signal on whichever task wrote, so this holds for Rea and Aether programs, applets, builtins in a subshell and the shell itself: a script at top level that writes to a pipe whose reader has gone, such as one opened with `exec 3> >(head -1)`, ends with 141, where it got a write error and carried on. Under `trap '' PIPE` the write still fails with `EPIPE` and the writer goes on.
- A builtin whose write fails under `trap '' PIPE` says `write error: Broken pipe` and gives status 1, as bash does; it gave 141 and said nothing. `yes` whose output fails says `yes: standard output: ...` and ends with 1, as GNU's does; its status was the error number.
- `micro` makes a new file or directory with the file mask of the shell that started it: `(umask 077; micro f)` saves `f` as `-rw-------`. It used the first tab's shell's mask, whatever its own shell's was, because the Go runtime calls the system's `open` and `mkdir` itself. Those calls now go through the app, which applies the starting shell's mask, so micro's backups and config files follow it too.
- `micro` gets each key as it is typed again. It got nothing until Enter, so Ctrl-Q seemed to do nothing, and the line typed next went to micro instead of the shell. The terminal now runs in raw mode while micro does, as it would for micro on Linux.
- `micro notes.txt` opens and saves `notes.txt` in the shell's directory. It used the app's own directory, the same one for every tab, so a file saved from `~/src` landed in `~`, and micro's `cd` command moved it for every tab. App paths such as `~/notes.txt` or `/home/notes.txt` now work in micro as well, because micro's file calls go through the app the way its `open` already did for the mask.
- `/proc/$$/fd/N` in a sourced file, `eval` or a pipeline stage sees the redirections of the group it is in: `{ echo a > /proc/$$/fd/1; } > f` writes `a` to `f`, as at the prompt and on Linux. It reached the shell's descriptor from before the redirection, the terminal. `ls /proc/$$/fd` lists the group's descriptors there too.
- A `/proc/<pid>/fd/N` link names what the descriptor is now: `readlink /proc/$$/fd/8` in `{ ...; } 8> g` gave the file from an earlier `8> f` if the two came within a quarter of a second.
- `$HOME` is `/home`, the name `pwd`, `realpath`, `readlink -f` and `readlink /proc/self/fd/N` give the home directory, as on Linux, where all of them agree. It was the device's path to it (`.../Documents/home`), so `readlink /proc/self/fd/3` on a file in your home, or `readlink -f /dev/stdout` with stdout on one, didn't give the path `$HOME` names it by. Nothing moved: your files, `~/.ssh` (keys, `config`, `known_hosts`), `~/.exshrc`, the history and the bytecode cache stay where they were, and the device's path still works. `cd` with no operand goes to `$HOME` as it is set, as in bash.
- `$TMPDIR` is `/tmp` and `$PATH` names the app's commands as `/bin`, the names everything else in the app uses. `$TMPDIR` was the device's path to your home directory, and `$PATH` held the device's path to the app's `bin`. A `~/.exshrc` from an earlier build has its one line that put that path in `PATH` rewritten at launch; nothing else in it changes.
- `/tmp` is emptied once per launch, as at boot on Linux. Opening a tab emptied it too, under whatever the other tabs were doing.
- `sed -i`, `cp -p` and `ln -L` work on a path written from the root, such as `/home/f`, and on `~/f` now that `~` is `/home`. They reached the device's own `/home` and failed: `sed: couldn't open temporary file`, `cp: preserving times`, `ln: failed to create hard link`.
- Pascal, Rea and CLike in the app have only their own builtins, as on a Mac or Linux, as Aether has since build 33. The shell's commands and its tools were theirs too: `cat('f')` and `basename('/a/b')` ran smallclue's commands, a program's own function `sum` drew a warning that it overrode a builtin, and `HasExtBuiltin`, `ExtBuiltinCategoryName` and `--dump-ext-builtins` listed the shell's commands as a `shell` category. Now `cat('f')` is `call to undefined function 'cat'` in CLike, `identifier 'cat' not in scope` in Rea and `Undefined global variable 'cat'` in Pascal, the same as on a Mac.

- Ctrl-S stops a terminal's output and Ctrl-Q starts it again, as on Linux, while `ixon` is set, which it is by default (`stty -ixon` turns it off). With `ixany` any key starts it. Echo typed while stopped shows when output starts, a program writing waits (or gets `EAGAIN`), and Ctrl-C or Ctrl-Z starts output again. `tcflow` works, and a packet-mode reader hears of a stop and a start. They were ordinary keys whatever `ixon` said.
- With `icanon` clear, the terminal still translates Return (`icrnl`, `inlcr`, `igncr`) and echoes (`echo`, `echoctl`) by their own flags, as Linux does. So `read -n 1` shows the key, as in bash, and Enter at a Pascal `ReadKey` gives `#10` on iOS as it already does on macOS and Linux.
- A terminal's keys that raise a signal send one signal per key, in the order typed, and drop echo not yet shown with the input they flush.
- A signal interrupts a read or write waiting on a terminal, as on Linux: a handler without `SA_RESTART` gets `EINTR`, one with it carries on, and a job stopped in a read and continued goes on reading.
- Changing a terminal from a background job (`stty`, `tcsetattr`, `tcflush`, `tcflow`, `tcsetpgrp`, `tcdrain`'s break) stops the job with `SIGTTOU`, unless it ignores or blocks that signal, as on Linux.
- A non-blocking write to a terminal returns how much it took, and a pty master only says it can be written when there is room.
- A pty master reads what its slave wrote before its last close, then `EIO`, and keys written meanwhile wait for the slave's next open. It read 0 at once and lost that output.
- Ctrl-C, Ctrl-\ and Ctrl-Z are signals from the terminal itself, as on Linux: a command sees `isig` set (`stty -a`), `stty -isig` makes them ordinary keys, and a program in raw mode reads them as bytes. They were made into signals by a reader in front of the terminal, and a command ran with `isig` clear.
- Closing a tab hangs up its shell with SIGHUP and SIGCONT, as closing a terminal window does on Linux. When a shell that leads its session ends, the job in the foreground on its terminal gets SIGHUP and the terminal stops being the session's (`/dev/tty` says `No such device or address`). A stopped job left without its shell gets SIGHUP and SIGCONT.
- Pascal `ReadKey`: Ctrl-C ends the program. It left only the procedure that called `ReadKey`, so a game reading keys in a procedure (DiceGame) carried on.

## Fixed in Pascal, CLike and Rea
- CLike: storing a character literal into a string (`s[i] = '-'`) stopped the program with "Type mismatch for character assignment". It had failed since CLike moved to the shared compiler in June; hangman5 died on its first line of play. A Char stored into a WideChar no longer warns "may lose precision".
- Pascal, CLike and Rea programs ended by Ctrl-C exit with status 130 on macOS and Linux, as on iOS. They exited 0, so a script carried on as if the program had finished.
- CLike: a function can call one defined further down the file, and a prototype (`int f(int);`) declares one, as in C. Such a call stopped the program with `Undefined global variable`, which kept the bundled `simple_web_server` from starting.
- CLike: `fopen(path, "w")` opens the file. A one-letter mode is a character literal, and `fopen` stopped with `fopen expects (path:string, mode:string)`.
- Pascal: calling a procedure or function that was never declared, or reading a variable that was never declared, is a compile error: `Undefined procedure or function 'foo'`, `Undefined variable 'z'`. Such a program used to compile, run up to that line and stop with `Undefined global variable`, so a mistake on a line that rarely runs went unnoticed. In the app, a shell command such as `cat('f')` is reported the same way.
- Pascal: a call to an undeclared routine in a branch that can never run, such as `if false then nosuch(1)` or the `else` of `if true then`, is a compile error too. The optimizer dropped such a branch before the check saw it, so the mistake was never reported.
- Pascal has the standard `Delete`, `Insert`, `Assigned`, `GetTickCount` and `Move`, and SysUtils has `GetEnvironmentVariable`; they behave as in Free Pascal. `SizeOf` takes a type name: `SizeOf(Integer)` is 4 and `SizeOf(TCell)` the size of the program's own type (it was 8, the size of a pointer, and a program's own type did not compile). A procedure variable can be set to `nil` (`cb := nil`). `Move` copies whole elements, and stops with an error instead of writing past the end of an array. Only Pascal has these routines: a CLike, Rea or Aether program can still name its own function `delete` or `move`. The bundled examples hangman to hangman5, LamdaCalc, GameOfLife and UI, which call them, run again.
- Pascal: an integer argument can go to a `Byte`, `Word` or subrange value parameter, as in Free Pascal: `uses Crt; Delay(30)` compiles (it failed with `argument 1 to 'crtmac.delay' expects type WORD but got INTEGER`). A variable's value wraps to the parameter's type (70000 into a `Word` is 4464), and a constant out of range compiles with a warning (`range check error while evaluating constants (70000 must be between 0 and 65535)`).
- Pascal: an open-array parameter (`v: array of Integer`) is indexed from 0 inside the routine, whatever the bounds of the array passed: `Low(v)` is 0 and `High(v)` is `Length(v) - 1`, as in Free Pascal. It kept the caller's bounds, so `for k := 0 to High(v)` failed on an `array[1..n]`. The bundled QuickSort example, which counted from 1 inside its open array, counts from 0.
- CLike and Rea have `strinsert(s, pos, t)` and `strdelete(s, pos, n)`, which return a new string with `t` inserted before position `pos`, or `n` characters removed from it; positions count from 1, as in `copy` and `pos`. Only CLike and Rea have them: a Pascal or Aether program can name its own function `strinsert`.
- Rea strings have `s.insert(pos, t)` and `s.remove(pos, n)`, which change the string in place, the same as `s = strinsert(s, pos, t)` and `s = strdelete(s, pos, n)`. The string can be a variable, a field or an array element; using either method as a value is a compile error that names the function to use instead.
- `simple_web_server` serves its pages. It called `pos` with its arguments reversed and loaded files without checking that they exist, so its first request ended it.
- Ctrl-C ends a Pascal, CLike or Rea program that is waiting in a socket call (`socketAccept`, a receive or a connect) on macOS and Linux. A server waiting for a connection, such as `simple_web_server`, went on waiting and the shell never got its prompt back.

## Differs from Linux on iOS
- `ip` changes nothing: `ip link set`, `ip address add` and `ip route add` say `RTNETLINK answers: Operation not permitted` with status 2, as for a normal user on Linux, and root gets the same answer. The app can't configure the device's network.
- `ip` shows every address as `valid_lft forever preferred_lft forever`, without `dynamic` or `temporary`, and prints no `qdisc` or `qlen`: iOS doesn't report them. iOS hides hardware addresses, so `link/ether` shows `02:00:00:00:00:00`.
- `ip neigh`, `ip rule` and the other objects past address, link and route aren't there, nor are `-s`, `-d` and batch mode.
